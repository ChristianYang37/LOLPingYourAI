## 1. #9：Electron 键盘输入被焦点检查拒绝

**结论：报告可信，属于需要优先处理的兼容问题。根因方向有较强证据；整合实现及验收状态见上表。**

- 贡献者的时间线中，点击成功，但 9 次 key/type 全部返回 `no focused control`；截图有光标。单凭光标不能证明原生 AX 焦点正确，但足以支持“用户可见焦点与 helper 读取结果不一致”。
- `native/desktop/WindowIdentity.swift` 的 `hasTargetFocus(requireInput: true)` 确实在读不到 `kAXFocusedUIElement` 时拒绝输入；`native/desktop/main.swift` 只等待 1 秒，代码里没有请求 `AXManualAccessibility`。
- #9 的补充 probe 报告：无请求时，连续约 8 秒返回 `kAXErrorNoValue`；设置 `AXManualAccessibility=true` 后，约 2 秒才出现 `AXTextArea`。这是贡献者提供的实验，尚未由本次工作独立复现，也没有完整 probe 源码/原始结构化报告随该 issue 发布。
- [Electron 官方文档](https://www.electronjs.org/docs/latest/tutorial/accessibility#macos)明确支持通过该属性启用 macOS 辅助功能，因此不是凭空猜测的 workaround。
- 他补充的旧版本成功、新版本失败对照支持“新增焦点检查导致拒绝”这一解释；两个运行的 SDK 和模型不同，不能当成严格单变量实验。错误发生在 helper 发键之前，也不能据此归因于 Claude 模型。

**推荐修复路径：**

1. 对已明确授权执行且身份已确认的目标，遇到 `no focused control` 时请求目标应用的 AX 树；检查返回码，区分 unsupported、no-value、权限错误。不要修改系统全局辅助功能设置。
2. 对成功接受请求的目标，给出有上限的冷启动等待，例如总计 3–5 秒；限制 AX 消息超时，轮询中仍检查前台进程、窗口 ID、所属窗口、弹窗与动作是否已取消。`AXManualAccessibility` 对其他应用可能不支持；不能假设所有窗口都适用。
3. 就绪后仍执行现有输入前身份/焦点检查，绝不因为 `NoValue` 就直接发送键盘事件。不要回退到“同一进程即可”或标题/尺寸匹配。
4. helper 每次动作都会重启，避免仅依赖 helper 进程内缓存。属性可提前在首次明确执行动作请求中触发，但只观察的 ping 不应为了读图就强行开启目标的完整 AX 树。
5. 日志记录属性返回码、首次可读耗时、拒绝原因与实际焦点所属窗口，避免记录用户输入正文。

**修复验收门槛：**每个样本都启动全新的 Electron Test Board，不能提前打开 Accessibility Inspector 或手动开启 AX 树；比较原 helper/新 helper 的点击→全选→输入→恢复；同时覆盖同进程两个同尺寸窗口、焦点切换、模态对话框、取消发生在等待期、目标关闭。另跑 Chrome、Safari、TextEdit。仅在测试板上 `app.setAccessibilitySupportEnabled(true)` 会掩盖产品问题，不能算修复。

此前已有窗口身份测试通过，并不推翻 #9：既有运行可能已经激活过 AX 树，不能将该解释当成已证实事实。应新增独立进程冷启动场景来检验。

## 2. 最大化失败／窗口超出屏幕

**结论：观察有证据，审查基线实现存在对应脆弱点；具体平台约束尚需隔离实验。**

`ai/desktop.mjs` 将 Electron 的 `workArea` 交给 native `resize`。macOS 实现先设置尺寸、等待 100 ms，再设置位置，随后只读回验证 700 ms；没有重新应用尺寸，也没有对部分成功做回滚。

从右下角直接放大窗口时，系统/应用可能先按旧位置限制尺寸，或移动时再次调整尺寸。这个方向可以解释报告中的部分现象，但尚不能断言 39 px 高度差一定来自菜单栏、Dock 或标题栏。

**方案：**记录 requested / AX / CG 实际矩形；保存原矩形；在目标身份保持不变时，先移入目标工作区，再设尺寸，再做一次位置/尺寸校正；使用有限次重试和稳定读回，而非无限重试或把误差阈值调大。固定大小窗口或最小尺寸超过工作区时，明确返回受限状态与实际边界；失败时尝试恢复原矩形，分别报告恢复是否成功。保持 `restore` 在失败后仍可使用。

**验收：**四角、负坐标副屏、Retina/混合 DPI、不同 Dock 位置、固定尺寸窗口；每次检查实际窗口矩形在工作区内，且恢复与原矩形一致。边界误差与系统约束分开测试。

## 3. 其他观察逐项判定

| 报告事项 | 当前代码判断 | 解决办法 / 验证 |
| --- | --- | --- |
| `question` 信号被拒绝 | 预期行为；公开 ID 是 `missing`，不是协议缺陷 | 工具示例使用 `missing`；错误提示列出合法 ID。无需修改信号语义或默默猜测未知 ID |
| 首次设置识别 Finder，但图中是设置窗口 | 源码支持这一风险路径，原运行素材已省略，仍需复现 | helper 枚举排除本应用 PID，截图却只隐藏 overlay，不隐藏 settings/reply card；因此可能定位到被本应用遮住的窗口，却抓到遮挡它的本应用。首次测试应隐藏设置窗口并等待合成器稳定，或显式指定一次性测试板并捕获该窗口。对任何异步捕获，应重新校验窗口身份/边界，避免定位与图像不一致 |
| `setupComplete` 一直 false | 尚未证实持久化缺陷 | 当前按钮明确发送 `{setupComplete:true}`，service 校验后写入 `ai-config`；测试 ping 不会自动完成设置。补齐“点击完成→IPC 成功→配置文件→退出重开”的独立证据。若只有测试 ping，false 属于当前设计；UI 应明确剩余步骤 |
| Save signal 没有反馈 | “完全没有反馈”与源码不符；可发现性问题成立 | 当前 `run()` 成功后已有顶部 `role=status` 的 Saved；Map emote 只是准备表单，不保存。将保存提示放到按钮旁，增加未保存状态、保存中/失败反馈，或把选择与保存合并成一个清楚的动作。测试 IPC 拒绝、保存成功、切换信号和重启 |
| 参考图与纯描述均标为 `vector-generated` | 输出方式标签正确，但来源信息缺失 | 分开保存 `method` 与 `referenceUsed`；后者必须由生成请求设置，不信任模型自己声明。界面组合显示“矢量生成 · 使用参考图” |
| 情绪回应中出现未请求的 `submit_icon` | 已确认缺少用途授权检查 | `submit_icon` 是共享 MCP 工具，桥接处理直接调用 `icons.submit`；普通情绪/观察上下文也能生成候选。使用只属于显式 Generate 请求的短期生成权限/独立 MCP 连接；普通 teammate 不授予该能力。取消/结束立即失效，不能用一个全局“正在生成”布尔值让并发会话借用权限。至少测试观察/情绪拒绝、合法生成成功、过期 token 拒绝和并发隔离 |
| `effectiveModel=default`，init 报具体模型 | 状态展示混淆了选择值与实际解析值 | Claude adapter 已将 init 的模型保存在 `this.model`，但 status 返回另一个 `effectiveModel`；分别暴露 selected / resolved / observedModel，UI 展示其来源，不把别名当实际模型 |
| effort 0/8 显示 low/max，但模型实际收到什么未证实 | 可确认适配器设置意图，不能确认后端执行 | 现有测试检查 `options.effort` 和 `applyFlagSettings` 入参；进一步记录 SDK 设置回执与模型目录支持档位。没有后端证据时标“已请求/SDK 已接受”，不声称从回复质量验证了思考强度 |
| 每轮出现额外账号 MCP connector | 旧安装包的已知状态，main 已由 #6 修复配置 | `strictMcpConfig:true` 和相应自动测试已经存在；仍需当前安装包的已登录 init 记录确认实际只加载项目 MCP，不重复提交相同改动 |
| 第一次参考图 SVG 被拒绝 | 安全校验正常，不应为了通过生成而放宽 | 保留外部/活动内容拒绝；修正生成提示并覆盖安全 SVG 回退与错误提示。第二次成功不证明第一张本应被接受 |
| 模型从历史补全被截断的文字 | 有限截图解释质量问题 | 提示将“当前可见文字”和“历史已知内容”分开；用截断内容和改变后的文字作负例，不靠放宽窗口权限解决 |

## 4. 尚未覆盖，不等于已经发现缺陷

- 编辑成功后的 Danger 恢复：被 #9 阻塞。修复焦点后，以测试板自身 value 检查前后内容，不能只看模型说“完成”。
- 停止超时的 UI：用可控假 adapter 不返回取消确认，检查 gate 已关闭、状态仍为 stopping/error、绝不误报 stopped；再做一次真实正在输入时的停止。现有取消/迟到 turn-start 测试不能代替超时 UI 测试。
- 当前版本关闭目标窗口的回访：关闭测试板后到期应失败并通知，不重绑同 PID/标题/坐标的新窗口；同时测重启后的 uncertain 状态。
- 多显示器、混合 DPI、四方向轮盘、穿透、音效：需要对应物理环境和人工验收；协议模拟不能升级为实机已通过。
- Copy：检查剪贴板文本与当前 task 完整文本一致，包含 Unicode、长文本与空回复；真实测试前保留原剪贴板并恢复。
- Windows 与当前 main 的已登录 Claude 全链路：此次工具整理没有补齐这两项实机证据。新工具可运行于 Windows，不等于 Windows desktop helper 已验收。
- exactly-once 回访：继续使用持久化调度器单元测试，并记录相关 ward/context ID 的完整运行事件。轮询看到 completed 只能证明终态，不能单独证明没有重复运行。
